## Методика

- Все прогоны — на прогретом Gradle-демоне, конфигурационный кэш и `org.gradle.caching=true` включены.
- Clean build: `gradlew clean`, затем замер `:app:assembleDebug`; для сравнения с baseline — с `--no-build-cache`.
- Incremental: повторный `:app:assembleDebug` без изменений (up-to-date). Отдельно указан первый прогон после clean, когда пересобирается config cache.
- Unit-тесты: удалены каталоги `build/test-results/testDebugUnitTest`, затем замер `testDebugUnitTest` (все модули). Повторный замер — только исполнение тестов.
- Instrumented: `connectedDebugAndroidTest` на SM-X400; устройство разбужено и не блокируется (в состоянии Dozing activity не стартует, Compose-тесты падают с `No compose hierarchies found`).
- Kover: `koverXmlReportDebug` для `:app`, `:core:data`, `:core:canvas`, `:feature:board`, `:feature:home`; суммарное покрытие — сумма LINE-счётчиков.

## Наблюдения и риски

- Clean build ускорился примерно на 21 % — ожидаемо: модули собираются параллельно, а build cache отдаёт результаты.
- Время unit-тестов выросло из-за роста числа тестов (259 против меньшего набора в монолите) и компиляции тестов в 6 модулях; чистое исполнение — ~3 s.
- APK по размеру практически не изменился: модуляризация не уменьшает код, а R8/resource shrinking в debug не применяется.
- Покрытие `:app` = 0 %: там остались только `MainActivity`/`AppContainer`/`AppNavHost`, на них нет unit-тестов (проверяются смоуком и instrumented).
- Долги: DAGP-советы (часть `api`/транзитивных зависимостей) не фатальны; `:app` всё ещё зависит от `:core:data` ради `AppContainer`; Kover не подключён к `:core:domain`.
